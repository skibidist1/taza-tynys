# Órleu Hack: план реализации трёх прототипов

Время на 25.11, 09:00: до сдачи 62 часа; заморозка фич 26.11, 22:00 (37 часов). Исполнители: три параллельных агента-сборщика (по одному на проект, зоны файлов не пересекаются), координатор и ревью — основная сессия.

## Общие решения (для всех трёх)

- **Стек:** статический сайт на чистом HTML/CSS/JS (ES-модули), без сборщика и без Node. Python 3.12 только для офлайн-пайплайнов (данные, эвалы). Внешние библиотеки (jsQR) кладём **локальным файлом** в `vendor/`, никаких CDN (иначе офлайн сломается).
- **PWA:** `manifest.webmanifest`, `sw.js` (cache-first для статики и данных, версионированный кэш, `skipWaiting`), иконка SVG и PNG 192/512 (PNG генерировать Python + Pillow, если есть, иначе только SVG).
- **Языки:** казахский и русский интерфейс (`i18n.js`), туризм ещё en и zh.
- **Деплой:** Vercel, отдельный проект на каждый прототип; деплоит координатор, не сборщик.
- **Git:** в каждом проекте свой `git init`, коммиты по шагам, без секретов.
- **Проверка:** `python3 -m http.server` + браузер. Каждый проект содержит `scripts/check.py`: валидация JSON-данных по схеме, наличие всех файлов из списка кэша `sw.js`, отсутствие ссылок на внешние CDN.
- **Честность:** никаких выдуманных цифр в интерфейсе; источник каждой цифры либо в коде, либо в README. Гипотезы помечать.
- **README:** каждый сборщик пишет `README.md` (запуск, демо-сценарий, архитектура, ИИ-часть, метрики, ограничения).

## Проект 1. `projects/izden` (кейс 3)

**Контракт данных** `data/bank.<lang>.json` (lang = kk | ru):
```json
{"version":1,"lang":"ru","units":[{
  "id":"ru-bus-01","grade":8,"title":"…","format":"table|continuous|notice|chart|mixed","context":"rural|urban|everyday",
  "blocks":[{"id":"b1","type":"p","text":"…"},{"id":"b2","type":"table","caption":"…","rows":[["…","…"]]}],
  "questions":[{"id":"q1","process":"locate|understand|evaluate","difficulty":1,
    "stem":"…","options":[{"id":"a","text":"…","correct":true},{"id":"b","text":"…","correct":false,"trap":"word_match","why":"…"}],
    "evidence":["b2:r3"],"hint_steps":["…","…"],"explain":"…"}]}]}
```
Типы ловушек (`trap`): `word_match` (слово из текста, но не ответ), `near_detail` (соседняя деталь), `outside_knowledge` (правдоподобно, но в тексте этого нет), `overgeneralize` (слишком общий вывод), `opposite` (перепутан смысл), `misread_table` (не та строка или колонка). Evidence указывает на блок (`b3`), предложение (`b3:s2`) или строку таблицы (`b2:r3`).

## Сверка со временем

Сумма: Ізден около 19 ч, Jolserik около 17,5 ч, Таза Тыныс около 15 ч. Агенты работают параллельно, поэтому по стене около 19 ч + 30% ≈ 25 ч → готово к 26.11, около 10:00, до заморозки (26.11, 22:00) остаётся запас. Затем ревью, деплой, презентации и видео.

## Раздача

Каждый проект отдаётся одному агенту-сборщику (general-purpose, сильная модель) с полным брифом: SPEC, этот план, свой раздел, правила честности. Генерация и слепая проверка контента идут внутри сборщика через его собственных сабагентов. Координатор после каждого отчёта делает `/verify` и `/hard-review`, затем деплой.

## Правки после независимой критики (25.11, 09:10)

- **Стратегия:** сдаём один кейс. На КТ-1 (25.11, 20:00) координатор выбирает, какой сдавать, по фактам дня. Остальные два прототипа доводятся до рабочего состояния, но слайды, видео и полировка идут только выбранному.
- **Деплой:** Vercel CLI 65.9 работает; в `vercel.json` для `sw.js` выставить `Cache-Control: no-cache`.
- **Проверка:** логику (BKT, кластеры, закат, модель ловушки) дублировать на Python для тестов (`tests/test_*.py`, запуск `python3 -m pytest` или `python3 tests/…`); UI координатор проверяет в Browser pane.
- **В каждом README:** раздел «Чем лучше существующих» (Ізден → тесты и онлайн-репетиторы; Jolserik → Organic Maps, 2GIS; Таза Тыныс → IQAir, AirKaz).
- **Ізден:** эвал BKT подаём как проверку работоспособности, а не как доказательство эффекта; «уровень PISA» переименовать в «условный уровень» с пояснением; сначала 10–12 отличных юнитов на язык, потом объём до 16+; в отчёте банка вести цифры брака конвейера (сгенерировано / забраковано / исправлено); пометка «казахский: ИИ + проверка, нужна вычитка носителем»; генератор QR — локальная JS-библиотека в vendor/.
- **Jolserik:** пакет включает и Кольсай, и Каинды (bbox 42.88–43.03, 78.22–78.52, в OSM 8 туалетов, 14 смотровых, 5 озёр). Высоты троп брать из Open-Meteo Elevation API при сборке пакета, время возврата по Нейсмиту (+1 ч на 600 м набора), с пометкой «оценка». Сервер жалоб только с реальным хранилищем; иначе шаг 8 убрать, жалобы и панель работают локально (одно устройство) + экспорт и импорт JSON / QR между устройствами. Китайский помечать «машинный перевод, проверен ИИ». Экран «Скачать офлайн» с прогрессом.
- **Таза Тыныс:** CAMS занижает пики (зима 2024/25: медиана PM2.5 34,5, p90 55, доля часов >55 около 10%). Пороги и тексты не должны обещать реальные значения; в UI указывать «модель CAMS, занижает пики в котловине». Попробовать найти реальные датчики (AirKaz/OpenAQ) для валидации; если без ключа нельзя, честно написать. Коэффициенты печей давать диапазонами со ссылками.
